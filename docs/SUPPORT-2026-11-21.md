## Reported failures

Two player exports show different failures: a script-compiler constant-pool error and a native package-preparation timeout. The first export contains the 2.0.1 installed payload and the second contains 2.0.0. Both summaries incorrectly reported 2.0.0 because the launcher version was hard-coded. Receipt hashes establish the distinction.

## Changes

- The spawned child process receives an empty signal mask. The parent background worker previously passed a blocked SIGCHLD signal to the .NET preparation helper, which then waited indefinitely for its completed child. The caller's signal mask is unchanged.
- Child process waiting, pipe errors, deadlines and bounded preparation logs now distinguish preparation failures instead of hiding them behind a timeout.
- The script compiler defers added fields until their new target and ancestor declarations are available. Existing resolved declarations retain their original path; inherited duplicate-field validation is retained. This fixes a reproduced order-dependent constant-pool error. The player's exact definition number has not been mapped because the export did not contain their script contents.
- Diagnostics include bounded preparation/native game logs, compiler and cache hashes, and the actual running bundle version.
- Valid AppleDouble sidecars in compiler hints are removed using the existing guarded cleanup. This addresses a secondary hint-reading error, not the primary compilation failure.

## Subsequent 2.0.2 startup crash

The 22:16 export identifies launcher 2.0.2 and its exact installed native manifest. Script compilation completed successfully, then the game terminated with signal 11 at game offset `0x1111098`, address `0x28`, under `ReadScriptsBundle`. This was a game crash, not a crash of the launcher. The export confirms the stock cache hash matches the local reproduction input.

Using 35 matching bundled framework files in the player's logged order and 17 separate runtime scripts reproduced the same fault and stack. No third-party player mod was required. The compiled native fields `morphResource` and `mesh` preceded their parent classes. Moving only the declaration file earlier made the same 2.0.2 compiler produce a cache that started successfully. That was a diagnostic control, not a proposed mod-file workaround.

The compiler now postpones allocating fields for new/source-defined targets until their target and ancestor declarations are ready. A final guard runs after pool cleanup and refuses native fields placed before their parent. Source files are not rewritten or sorted. Independent scans found zero forward or self-parent definitions in the corrected 52-script and 234-script outputs. Legal forward references remain allowed. The correction passed 77 compiler/core tests, Clippy and independent review.

The corrected original-order 52-script cache reached the title screen and F1 console with normal exit. The corrected 234-script cache reached the main menu and F1 console, completed Codeware script binding and reported healthy initialization of Native Settings, Vehicle Call Cost, Native Interactions and ITP. No save was loaded for these startup checks. The minimal 52-script fixture deliberately omits optional ITP helper sources and is not a full mod-compatibility test.

The normal signed 2.0.3 app's compiler also passed the original failing 52-script startup. A separate disposable fixture verified exact 2.0.2 receipt upgrades, missing-compiler repair, interrupted-update rollback, preservation of edited files and the actual preparation components with the two production script roots. Only the compiler pair changed among installed payload files. The fixture's game identity is synthetic; startup is checked separately against the real executable. Neither fixture testing nor notarization establishes affected-player recovery.

The full cache produced by those signed preparation components was subsequently launched against the real game executable. It reached the main menu and F1 console, initialized the selected modules and exited normally. No save was loaded. This closes the gap between compiling the final signed payload and testing its output at startup; affected-player gameplay remains unverified.

The normal 2.0.3 app and DMG received Accepted notarization results and passed stapling and Gatekeeper verification. Artifact checksums and validation limits are recorded in `RELEASE-2.0.3-VALIDATION.json`. No release was pushed or uploaded.
